# durable-saga

A saga across five independently transactional services, with an explicit
pivot, a compensation chain, a delayed carrier callback, two states a person
owns, and a failure-matrix runner that injects a fault at every point of every
step and reports what the system actually did.

Companion module for Article 18, *Sagas Without Hand-Waving*.

```
make verify
```

No cloud project, no credentials, no network, no runtime dependencies.
`typescript` and `@types/node` are development dependencies and are needed only
for the strict type check.

## What is here

| path | what it holds |
|---|---|
| `src/saga.ts` | **the definition.** Steps, participants, compensations, the pivot, the state machine, and the layout the diagrams are drawn from |
| `src/participants.ts` | five service simulators, each with its own store and its own effect ledger |
| `src/orchestrator.ts` | the orchestrator; everything durable is in `SagaStore`, so a restart is a new instance over the same store |
| `src/audit.ts` | **the auditor.** Reads the participants' effect ledgers and nothing else |
| `src/matrix.ts` | the failure-matrix runner |
| `src/svg.ts` | the diagram generator, including the assertion that no arrow passes through a box |
| `src/controls.ts` | each mutation paired with the probe that must notice it |
| `docs/SAGA.md` | generated from `src/saga.ts`; `make verify` fails if it drifts |
| `results/` | generated by `make report`; byte-identical on re-run |

## The saga

Six steps across five services. The pivot is `capture_payment`: before it, every
step has a compensation; from it onward there is nothing to go back to, so steps
are retried and then handed to a person.

| # | step | service | compensation |
|---:|---|---|---|
| 1 | `reserve_stock` | inventory | `release_stock` |
| 2 | `authorize_payment` | payments | `void_authorization` |
| 3 | `book_shipment` | fulfilment (answers by callback) | `cancel_shipment` |
| 4 | `capture_payment` | payments | **none — this is the pivot** |
| 5 | `post_ledger_entry` | ledger | none; retried |
| 6 | `send_confirmation` | notifications | none; irreversible, and last for that reason |

The full generated table, including why each step sits where it does, is in
[`docs/SAGA.md`](docs/SAGA.md).

## The part worth reading

**The compensation chain walks what was *dispatched*, not what *succeeded*.** A
step whose answer never arrived has, as far as anyone here knows, happened.
Switching this off is one of the eight negative controls, and it leaks a real
carrier booking into a saga that believes it compensated everything.

**The failure matrix is scored by a party that never ran the saga.** The
orchestrator reports where it thinks the saga got to; `src/audit.ts` reports
what the five services actually did, computed from their own effect records
with no shared helper. A row where the two disagree is a defect in the
orchestrator. One mutation — `orchestrator-forgets-compensation` — makes the
saga record a compensation it never sent, and only the auditor notices.

**Both rendered diagrams are generated from the definition** and `make verify`
fails if either has drifted. The generator refuses to emit a drawing in which
any arrow passes through any box, which is a rule this programme has broken by
hand three times.


## Determinism

Nothing in `src/` reads a clock. Every function that needs the time takes it as
a parameter, every run starts at a fixed instant, and `make report` produces
byte-identical output on re-run. Results are labelled **Simulated result**
because they are: this module models platform behaviour locally and creates no
cloud resources.
